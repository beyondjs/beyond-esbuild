# Documentation instructions

Keep this repository's guides self-contained, in English, and linked from the local index. Describe contracts and commands without relying on sibling checkouts. External source coordinates must include a revision and path where practical. Separate executed results from source observations and proposals. Preserve accurate limits; map coverage is not an exhaustive line-by-line audit. Update the relevant guide when an assessment changes and validate local links. Fixtures and executable tests belong outside this directory.

Apply the root portability rule to guides, handoffs and retained evidence; do not copy machine-specific paths from local diagnostics.

`docs/` contains durable maintained product/developer documentation and reusable evidence. Temporary handoffs, session notes and execution plans belong in `docs-temp/`. Before removing or archiving temporary material, carry lasting decisions and relevant evidence into the maintained guide. Canonical onboarding and contracts must remain understandable without disposable handoff files. Preserve upstream documents and their attribution; add Beyond-specific guides instead of repurposing upstream explanations.
